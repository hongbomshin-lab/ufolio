# Google Sheets 실제 설치·운영 가이드

이 가이드는 기존 케이스장 시트를 변경하지 않고, 학생 93명·U-FOLIO 마스터 206개를 관리자 전용 비교 시스템에 연결하는 순서입니다.

**2026-08-13 개편:** 스프레드시트가 ①(사이트 인증)·②(통합관리자) 두 개에서 **한 개**로 통합됐습니다. 현재 관리자가 평소에 보는 시트는 6개이고, 나머지는 전부 숨겨져 있습니다.

## 준비된 결과물

- `outputs/…/01_유폴리오_통합.xlsx` — `node scripts/build-spreadsheets.mjs <명단.tsv>` 로 생성 (구조 확인·비상 복구용)
- `apps-script/Code.gs`, `CaseSheetCore.gs`, `CaseSheetDefaults.gs`, `CaseSheetSync.gs`, `CaseSheetDashboard.gs`, `SystemSetup.gs`

권장 운영 경로는 **기존 ① 사이트 인증 파일을 그대로 통합 파일로 승격**하는 것입니다. 웹 앱 배포와 RAW 데이터가 이미 그 파일에 있으므로 북마클릿·웹 앱을 다시 배포할 필요가 없습니다.

## 1. 기존 2-파일 구조에서 통합하기 (이미 운영 중인 경우)

1. ① 사이트 인증 파일에서 `확장 프로그램 → Apps Script`를 엽니다.
2. 6개 스크립트 파일을 저장소 최신 내용으로 교체합니다. `CaseSheetDashboard.gs`는 새로 만듭니다.
3. 파일을 새로고침하고 `유폴리오 통합관리 → ② 관리자 파일 가져오기 (1회)`를 실행합니다.
   - ②의 `현황시트연결`(입력해 둔 URL 포함), `항목매핑`, `현황최신`, `동기화로그`가 이 파일로 복사됩니다.
   - 기본 연결·매핑 행(코드에 정의된 소스키·매핑키)은 이어지는 화면 구성 적용에서 코드 기준으로 맞춰집니다. URL과 직접 추가한 행은 보존됩니다.
   - 이어서 화면 구성 적용과 전체 동기화가 자동 실행됩니다.
4. `대시보드`·`비교결과`가 채워졌는지 확인합니다.
5. 이후 ② 파일은 사용하지 않습니다. 보관하거나 휴지통으로 옮깁니다.

## 2. 처음부터 새로 설치하는 경우

1. `01_유폴리오_통합.xlsx`를 관리자 Google Drive에 업로드하고 `파일 → Google 스프레드시트로 저장`으로 변환합니다.
2. `학생명단`(93행)과 `마스터항목`(206행)을 확인합니다.
3. Apps Script에 6개 파일을 붙여넣고 `유폴리오 통합관리 → 화면 구성 새로 적용`을 실행합니다.
4. `현황시트연결` E열에 원본 URL을 입력합니다(아래 3장).
5. `연결 검사 → 지금 전체 동기화`를 실행합니다.
6. Apps Script를 웹 앱으로 배포하고 `/exec` URL을 `config.js`에 입력합니다.

## 3. 원본(케이스장) 시트 연결

현재 기본 연결은 16개이며 활성 13개, 비활성 3개입니다. 소아치과 총점 현황은 `PED_SCORE`로 추가됩니다.

1. Apps Script를 실행한 관리자 Google 계정을 각 원본 Google Sheets의 `뷰어`로 추가합니다.
2. 원본 링크를 복사해 `현황시트연결` E열 `스프레드시트 URL`의 해당 소스 행에 붙여넣습니다.
3. 파일명 대신 `소스키`와 `시트명`을 보고 맞는 행에 넣습니다. 같은 파일을 사용하는 두 소스 행에는 같은 URL을 넣습니다.
4. 원본 시트의 셀·수식·탭명은 수정하지 않습니다.

URL이 들어가야 하는 소스키: `CONS_SCORE`, `PED_CHART`, `PED_SCORE`, `PERIO`, `OM`, `EXT`, `PATH`, `PROS`, `OMS`, `OMS_STAGE`, `ORTHO`, `RADIO`, `PROS_TOTAL`

URL이 필요 없는 소스키: `IMPLANT`, `CONS_SURGERY`, `PROS_CHART` (셋 다 비활성이라 읽지 않습니다)

`IMPLANT`는 과거 학년·예시 자료로 확인되어, `CONS_SURGERY`는 보존 수술 점수를 `CONS_SCORE`(점수판) F열에서 받게 되어, `PROS_CHART`는 실시간 현황조사용이라 비교에 쓰지 않게 되어 기본적으로 `N`(비활성), `보류`입니다.

### 소아치과 3-2학기 총점 현황 추가

기존 운영 파일에 적용하는 순서:

1. Apps Script의 `CaseSheetCore.gs`, `CaseSheetDefaults.gs`, `SystemSetup.gs`를 최신 파일로 교체하고 저장합니다.
2. 운영 시트를 새로고침하고 `유폴리오 통합관리 → 소아치과 총점 현황 적용`을 실행합니다.
3. `현황시트연결`에서 `PED_SCORE` 행 E열에 총점 현황 원본 링크를 입력합니다. 탭은 `시트1`, 출석번호는 A열, 이름은 B열, 데이터 시작은 4행입니다. 3행 예시는 제외합니다.
4. `지금 전체 동기화`를 실행하고 아래 8개 항목을 확인합니다.

전용 메뉴는 총점 현황의 연결·매핑과 아래 항목들의 `측정값설정`을 적용합니다. 기존 연결 URL과 다른 항목의 측정값은 보존됩니다. 기존 파일은 측정값설정이 매핑보다 우선하므로 `화면 구성 새로 적용`만 실행하면 교픽·단타·기공이 예전 승인수 설정을 유지할 수 있습니다. 이번 추가에는 전용 메뉴를 사용하세요. 반복 실행해도 연결·매핑이 중복되지 않습니다. 웹 앱 수신기와 북마클릿은 변경하지 않으므로 이 추가만을 위해 웹 앱을 재배포할 필요는 없습니다.

차팅은 총점 현황 `PED_SCORE`(우선순위 90)를 기존 `PED_CHART`(80)보다 우선하며 두 값을 합산하지 않습니다. 기존 차팅 연결은 남아 있고 새 총점 현황의 학생별 집계가 아직 없으면 기존 집계가 사용됩니다. 새 원본 갱신이 실패하면 기존 동기화 정책에 따라 마지막 정상 총점 집계를 `원본노후`로 유지합니다.

차팅·Q-ray 등 원본의 제출 건수는 유폴리오 승인수와 비교하며, 승인대기는 `미승인` 열로 따로 표시합니다. 자율턴 점수·관련 계산 열, 교픽 횟수, 단타 예비승인, 4-1/전체 차팅, 비고, 총점은 비교하지 않습니다. 원본 파일은 변경하지 않습니다.

## 4. 평소에 보는 시트 (전부 6개)

| 시트 | 용도 |
|---|---|
| `대시보드` | 유폴리오 최신 제출 기준 **항목 × 학생(출석번호 순) 매트릭스**. 항목별 평균 포함. 아직 한 번도 안 보낸 학생은 회색 머리글로 표시. **항목 행을 클릭하면 우측 상단 그래프에 그 항목의 값 분포(막대)가 뜸.** |
| `비교결과` | 출석번호 / 학번 / 이름 / 과 / 현황표시명 / 측정값 / 현황값 / 제출건수 / 승인수 / 미승인 / 환자수 / 점수 / 최신 유폴 인증. 인증을 안 보낸 조합은 값 전부 `미인증`. 정책상 점수를 수집하지 않는 항목은 점수에 `안받음`. |
| `현황시트연결` | 원본 시트 URL·연결 상태. 구조가 바뀔 때만 수정. |
| `지각자` | 최다 제출일을 기준으로 미인증·이전 날짜 인증·지각을 구분하고 마지막 전송 시각 표시 |
| `보철비교` | 보철과 현황조사·개인별 토탈·유폴리오 집계 비교 |
| `측정값설정` | 항목별로 승인수/환자수/점수 중 비교·집계 기준 선택. 바꾼 뒤 `지금 전체 동기화` 실행. |

비교결과 색상(동기화 때 자동으로 칠해짐): **빨강 = 미인증**, **노랑 = `측정값`으로 고른 값이 현황값과 다름**, **초록 = 일치**.

`제출건수`는 유폴리오 화면의 "제출 건수"와 같은 **총 제출 건수(승인 + 미승인)**, `미승인`은 아직 사인(승인)되지 않은 건수입니다. `최신 유폴 인증`은 그 학생이 마지막으로 북마클릿을 보낸 시각입니다.

RAW 시트에는 학생×실습차수별 **최신 제출만** 유지됩니다(재제출 시 이전 행 자동 삭제). 예전에 쌓인 중복은 메뉴 `유폴리오 통합관리 → RAW 과거 제출 정리(최신만 남기기)`로 1회 정리합니다.

치주과 `Flap Assist`·`Implant Assist`, 구강악안면외과의 `수술실-` 5개 항목, 영상치의학과 `나절별 임상참여 → 판독 토론 및 평가`는 점수를 수집하지 않습니다. 승인수·미승인·환자수는 그대로 유지하며 점수는 `안받음`으로 표시합니다. 정책 적용 전에 저장된 점수는 메뉴 `유폴리오 통합관리 → 점수 안받음 정책 기존 RAW 적용`을 한 번 실행해 삭제한 뒤 전체 동기화합니다.

나머지 시트(`항목매핑`, `미매핑항목`, `연결진단`, `동기화로그`, `현황최신`, `유폴리오최신`, `마스터항목`, `학생명단`, `RAW`, `전송기록`, `설정`, `차트데이터`, `사용안내`)는 시스템 운영용으로 숨겨져 있습니다. 좌측 하단 시트 목록(☰)에서 다시 열 수 있습니다. 문제가 생기면 `연결진단`과 `동기화로그`부터 확인합니다.

### 지각자 시트

`지금 전체 동기화`와 새벽 자동 동기화 때 `지각자` 시트를 생성·갱신합니다. 기존 운영 파일은 Apps Script의 `CaseSheetSync.gs`, `SystemSetup.gs`를 최신 내용으로 교체·저장한 뒤 전체 동기화를 실행하면 됩니다. 별도 시트 생성이나 웹 앱 재배포는 필요 없습니다.

- 기준일은 학생명단에 있는 학생들의 **마지막 전송일 중 가장 많은 날짜**입니다. 한 학생이 수백 개 점수 항목을 보내도 한 명으로 계산합니다. 최다 인원이 같은 날짜가 여러 개면 더 최근 날짜를 택합니다.
- 날짜는 **한국 시간(Asia/Seoul) 00:00:00**에 바뀝니다. 같은 날짜의 00:01과 23:59는 같은 날 제출로 처리합니다.
- 마지막 전송일이 기준일보다 늦으면 `지각`, 이르면 `이전 날짜 인증`, 전송 기록이 없으면 `미인증`으로 표시합니다. 기준일과 같은 학생은 제외합니다.
- 표에는 출석번호·학번·이름·구분·마지막 전송 시각·기준일 대비 일수를 표시합니다. 시각은 한국 시간 `yyyy-mm-dd hh:mm:ss`, 전송 기록이 없으면 `미인증`입니다. 이전 날짜의 일수는 음수, 지각은 양수입니다.
- 정렬은 미인증(출석번호순), 이전 날짜 인증(오래된 전송순), 지각(늦은 전송순)입니다. 같은 시각이면 출석번호순입니다.
- 상단에 자동 기준일과 해당 날짜 인원수를 표시합니다. 전원이 미인증이면 기준일 없음과 전체 명단을, 전원이 같은 날짜에 인증했으면 `해당 학생 없음`을 표시합니다.

이 목록은 고정 마감일이나 최초 제출 이력이 아니라 **최신 전송 날짜의 분포**를 기준으로 매번 계산합니다. 따라서 재전송하면 마지막 시각과 분류가 바뀔 수 있고, 기준일도 달라질 수 있습니다. 원본 현황을 읽는 동안 새 제출이 들어오면 쓰기 잠금을 얻은 뒤 RAW를 다시 읽어 반영합니다. 특정 과의 원본 동기화가 실패해도 이 목록은 유폴리오 전송 기록으로 갱신됩니다.

## 5. 측정값설정의 동작

- 각 마스터 항목(206개)마다 승인수/환자수/점수 드롭다운이 있습니다.
- 기본값은 검토 완료된 기본 매핑이 쓰던 측정값이고, 매핑이 없는 항목은 승인수입니다.
- 대시보드의 항목별 평균·학생별 값, 비교결과의 `측정값`(비교 기준)이 모두 이 설정을 따릅니다.
- 대상이 여러 항목인 매핑(예: 세 레진 practice 합계)은 첫 대상 항목의 설정을 따릅니다.

## 6. 항목매핑(숨김)의 집계식

제한 집계식:

- `VALUE(C)` / `NUMBER_OR_ZERO(C)`: C열 숫자
- `NONEMPTY_AS_ONE(C)`: 값이 있으면 1, 없으면 0
- `HAS_STATUS_O(C)`: 독립된 `O` 또는 날짜와 함께 적힌 `O`만 1
- `SUM(C,D)`: 지정 열의 숫자 합
- `COUNT_NONEMPTY(E:H)`: 범위에서 비어 있지 않은 셀 수
- `COUNT_STATUS(E:V,완)`: 범위에서 `완`과 정확히 같은 셀 수
- `COUNT_STATUS(M:M,완료,차팅 미승인)`: 지정한 상태 중 하나와 정확히 같은 셀 수. 한 셀은 최대 1건이며 `미완료`는 일치하지 않습니다.

원본 셀이 비어 있으면 집계식 종류와 상관없이 0으로 계산합니다("아직 안 적음" = 0건).

검토상태가 `승인`인 매핑만 비교결과에 올라갑니다. `검토필요`·`보류`는 (숨김) `미매핑항목`에서만 관리합니다.

## 7. 연결 오류가 날 때

`현황시트연결` N열 상태와 O열 오류, (숨김) `연결진단`을 확인합니다. 연결 오류는 대개:

- URL이 비어 있거나 Google Sheets URL 형식이 아님
- 관리자 계정에 뷰어 권한이 없음
- 원본 탭명이 바뀜
- 설정한 열이나 시작행이 실제 구조와 달라짐

원본 탭이나 열이 바뀌었을 때는 설정 행만 수정하고 다시 연결 검사·동기화합니다. 동기화가 실패한 소스는 마지막 정상값을 유지합니다(`원본노후`).

## 8. 새 현황시트 추가

### 원본 무수정 방식

1. `현황시트연결`에 새 소스키와 URL·탭·열·시작행을 추가합니다.
2. (숨김) `항목매핑`에 해당 소스키, 집계식, U-FOLIO 대상, 우선순위를 추가합니다.
3. 검토상태는 `검토필요`로 시작하고, 값이 맞을 때만 `승인`합니다.
4. 직접 추가한 행은 `화면 구성 새로 적용`을 다시 돌려도 그대로 보존됩니다. 반대로 코드에 정의된 기본 행은 활성·검토상태·집계식이 항상 코드(GitHub) 기준으로 되돌아가므로, 기본 행을 바꾸고 싶으면 시트가 아니라 저장소 `CaseSheetDefaults.gs`를 고칩니다.

### `_UFOLIO_EXPORT` 예외

원본 구조가 병합 셀·환자별 반복 블록 때문에 안전하게 집계하기 어려운 경우에만 케이스장과 합의해 숨김 `_UFOLIO_EXPORT` 탭을 추가할 수 있습니다.

| 열 | 내용 |
|---|---|
| A | 출석번호 |
| B | 이름 |
| C | 완료 집계 |
| D | 예정 집계 |
| E | 인증대상 집계 |

환자 이름·번호, 담당자, 날짜, 상세 메모는 이 탭에 포함하지 않습니다.

## 9. 웹 앱 배포와 북마클릿 시험

1. Apps Script `배포 → 새 배포`, 유형 `웹 앱`, 실행 사용자 `나`, 액세스 `모든 사용자`
2. `/exec` URL을 저장소 `config.js`의 `WEB_APP_URL`에 입력
3. `npm.cmd test`
4. GitHub main 푸시 후 Vercel 재배포
5. 표본 학생 계정에서 북마클릿 전송 → (숨김) `전송기록` 성공과 `RAW` 행 확인
6. 수동 동기화 후 비교결과·대시보드 확인

Apps Script 시간 기반 트리거는 정확히 03:00이 아니라 새벽 3시대에 실행될 수 있습니다. 필요할 때는 메뉴로 즉시 동기화할 수 있습니다.

## 개인정보 경계

- 이 파일은 관리자만 열람합니다. 학생과 공유하지 않습니다.
- 공개 GitHub/Vercel에는 학생명단·점수·원본 URL이 없습니다.
- 원본에서 중앙으로 저장되는 값은 학생 식별값과 항목별 집계뿐입니다.
- 원본 상세 열은 매핑식에 포함되지 않으면 읽지 않습니다.

- 원본 접근 권한, Apps Script 실행 승인, 웹 앱 배포는 로컬 코드가 대신 수행할 수 없으며 관리자 Google 계정에서 직접 해야 합니다.
