# Google Sheets 실제 설치·운영 가이드

이 가이드는 기존 케이스장 시트를 변경하지 않고, 학생 93명·U-FOLIO 마스터 206개를 관리자 전용 비교 시스템에 연결하는 순서입니다.

**2026-08-13 개편:** 스프레드시트가 ①(사이트 인증)·②(통합관리자) 두 개에서 **한 개**로 통합됐습니다. 관리자가 평소에 보는 시트는 4개뿐이고, 나머지는 전부 숨겨져 있습니다.

## 준비된 결과물

- `outputs/…/01_유폴리오_통합.xlsx` — `node scripts/build-spreadsheets.mjs <명단.tsv>` 로 생성 (구조 확인·비상 복구용)
- `apps-script/Code.gs`, `CaseSheetCore.gs`, `CaseSheetDefaults.gs`, `CaseSheetSync.gs`, `CaseSheetDashboard.gs`, `SystemSetup.gs`

권장 운영 경로는 **기존 ① 사이트 인증 파일을 그대로 통합 파일로 승격**하는 것입니다. 웹 앱 배포와 RAW 데이터가 이미 그 파일에 있으므로 북마클릿·웹 앱을 다시 배포할 필요가 없습니다.

## 1. 기존 2-파일 구조에서 통합하기 (이미 운영 중인 경우)

1. ① 사이트 인증 파일에서 `확장 프로그램 → Apps Script`를 엽니다.
2. 6개 스크립트 파일을 저장소 최신 내용으로 교체합니다. `CaseSheetDashboard.gs`는 새로 만듭니다.
3. 파일을 새로고침하고 `유폴리오 통합관리 → ② 관리자 파일 가져오기 (1회)`를 실행합니다.
   - ②의 `현황시트연결`(입력해 둔 URL 포함), `항목매핑`(검토상태 포함), `현황최신`, `동기화로그`가 이 파일로 복사됩니다.
   - 이어서 화면 구성 적용과 전체 동기화가 자동 실행됩니다.
4. `대시보드`·`비교결과`가 채워졌는지 확인합니다.
5. 이후 ② 파일은 사용하지 않습니다. 보관하거나 휴지통으로 옮깁니다.

## 2. 처음부터 새로 설치하는 경우

1. `01_유폴리오_통합.xlsx`를 관리자 Google Drive에 업로드하고 `파일 → Google 스프레드시트로 저장`으로 변환합니다.
2. `학생명단`(93행)과 `마스터항목`(206행)을 확인합니다.
3. Apps Script에 6개 파일을 붙여넣고 `유폴리오 통합관리 → 화면 구성 새로 적용`을 실행합니다.
4. `현황시트연결` E열에 원본 URL을 입력합니다(아래 3장).
5. `연결 검사 → 지금 전체 동기화`를 실행합니다.
6. Apps Script를 웹 앱으로 배포하고 `/exec` URL을 `config.js`에 입력합니다.

## 3. 원본(케이스장) 시트 연결

현재 기본 소스는 논리적으로 11개입니다. 발치·임플란트가 한 파일의 서로 다른 탭이므로 실제 원본 파일은 10개입니다.

1. Apps Script를 실행한 관리자 Google 계정을 각 원본 Google Sheets의 `뷰어`로 추가합니다.
2. 원본 링크를 복사해 `현황시트연결` E열 `스프레드시트 URL`의 해당 소스 행에 붙여넣습니다.
3. 파일명 대신 `소스키`와 `시트명`을 보고 맞는 행에 넣습니다. 같은 파일을 사용하는 두 소스 행에는 같은 URL을 넣습니다.
4. 원본 시트의 셀·수식·탭명은 수정하지 않습니다.

URL이 들어가야 하는 소스키: `CONS_SCORE`, `CONS_SURGERY`, `PED_CHART`, `PERIO`, `OM`, `EXT`, `IMPLANT`(비활성), `PATH`, `PROS`, `OMS`, `OMS_STAGE`

`IMPLANT` 탭은 과거 학년·예시 자료로 확인되어 기본적으로 `N`(비활성), `보류`입니다. 정상 상태는 활성 소스 10개 + `IMPLANT` 1개 비활성입니다.

## 4. 평소에 보는 시트 (전부 4개)

| 시트 | 용도 |
|---|---|
| `대시보드` | 유폴리오 최신 제출 기준 **항목 × 학생(출석번호 순) 매트릭스**. 항목별 평균 포함. 아직 한 번도 안 보낸 학생은 회색 머리글로 표시. **항목 행을 클릭하면 우측 상단 그래프에 그 항목의 값 분포(막대)가 뜸.** |
| `비교결과` | 출석번호 / 학번 / 이름 / 과 / 현황표시명 / 측정값 / 현황값 / 제출건수 / 승인수 / 미승인 / 환자수 / 점수 / 최신 유폴 인증. 인증을 안 보낸 조합은 값 전부 `미인증`. |
| `현황시트연결` | 원본 시트 URL·연결 상태. 구조가 바뀔 때만 수정. |
| `측정값설정` | 항목별로 승인수/환자수/점수 중 비교·집계 기준 선택. 바꾼 뒤 `지금 전체 동기화` 실행. |

비교결과 색상(동기화 때 자동으로 칠해짐): **빨강 = 미인증**, **노랑 = `측정값`으로 고른 값이 현황값과 다름**, **초록 = 일치**.

`제출건수`는 유폴리오 화면의 "제출 건수"와 같은 **총 제출 건수(승인 + 미승인)**, `미승인`은 아직 사인(승인)되지 않은 건수입니다. `최신 유폴 인증`은 그 학생이 마지막으로 북마클릿을 보낸 시각입니다.

RAW 시트에는 학생×실습차수별 **최신 제출만** 유지됩니다(재제출 시 이전 행 자동 삭제). 예전에 쌓인 중복은 메뉴 `유폴리오 통합관리 → RAW 과거 제출 정리(최신만 남기기)`로 1회 정리합니다.

나머지 시트(`항목매핑`, `미매핑항목`, `연결진단`, `동기화로그`, `현황최신`, `유폴리오최신`, `마스터항목`, `학생명단`, `RAW`, `전송기록`, `설정`, `차트데이터`, `사용안내`)는 시스템 운영용으로 숨겨져 있습니다. 좌측 하단 시트 목록(☰)에서 다시 열 수 있습니다. 문제가 생기면 `연결진단`과 `동기화로그`부터 확인합니다.

## 5. 측정값설정의 동작

- 각 마스터 항목(206개)마다 승인수/환자수/점수 드롭다운이 있습니다.
- 기본값은 검토 완료된 기본 매핑이 쓰던 측정값이고, 매핑이 없는 항목은 승인수입니다.
- 대시보드의 항목별 평균·학생별 값, 비교결과의 `측정값`(비교 기준)이 모두 이 설정을 따릅니다.
- 대상이 여러 항목인 매핑(예: 세 레진 practice 합계)은 첫 대상 항목의 설정을 따릅니다.

## 6. 항목매핑(숨김)의 집계식

제한 집계식:

- `VALUE(C)` / `NUMBER_OR_ZERO(C)`: C열 숫자
- `NONEMPTY_AS_ONE(C)`: 값이 있으면 1, 없으면 0
- `HAS_STATUS_O(C)`: 독립된 `O` 또는 날짜와 함께 적힌 `O`만 1
- `SUM(C,D)`: 지정 열의 숫자 합
- `COUNT_NONEMPTY(E:H)`: 범위에서 비어 있지 않은 셀 수
- `COUNT_STATUS(E:V,완)`: 범위에서 `완`과 정확히 같은 셀 수

원본 셀이 비어 있으면 집계식 종류와 상관없이 0으로 계산합니다("아직 안 적음" = 0건).

검토상태가 `승인`인 매핑만 비교결과에 올라갑니다. `검토필요`·`보류`는 (숨김) `미매핑항목`에서만 관리합니다.

## 7. 연결 오류가 날 때

`현황시트연결` N열 상태와 O열 오류, (숨김) `연결진단`을 확인합니다. 연결 오류는 대개:

- URL이 비어 있거나 Google Sheets URL 형식이 아님
- 관리자 계정에 뷰어 권한이 없음
- 원본 탭명이 바뀜
- 설정한 열이나 시작행이 실제 구조와 달라짐

원본 탭이나 열이 바뀌었을 때는 설정 행만 수정하고 다시 연결 검사·동기화합니다. 동기화가 실패한 소스는 마지막 정상값을 유지합니다(`원본노후`).

## 8. 새 현황시트 추가

### 원본 무수정 방식

1. `현황시트연결`에 새 소스키와 URL·탭·열·시작행을 추가합니다.
2. (숨김) `항목매핑`에 해당 소스키, 집계식, U-FOLIO 대상, 우선순위를 추가합니다.
3. 검토상태는 `검토필요`로 시작하고, 값이 맞을 때만 `승인`합니다.

### `_UFOLIO_EXPORT` 예외

원본 구조가 병합 셀·환자별 반복 블록 때문에 안전하게 집계하기 어려운 경우에만 케이스장과 합의해 숨김 `_UFOLIO_EXPORT` 탭을 추가할 수 있습니다.

| 열 | 내용 |
|---|---|
| A | 출석번호 |
| B | 이름 |
| C | 완료 집계 |
| D | 예정 집계 |
| E | 인증대상 집계 |

환자 이름·번호, 담당자, 날짜, 상세 메모는 이 탭에 포함하지 않습니다.

## 9. 웹 앱 배포와 북마클릿 시험

1. Apps Script `배포 → 새 배포`, 유형 `웹 앱`, 실행 사용자 `나`, 액세스 `모든 사용자`
2. `/exec` URL을 저장소 `config.js`의 `WEB_APP_URL`에 입력
3. `npm.cmd test`
4. GitHub main 푸시 후 Vercel 재배포
5. 표본 학생 계정에서 북마클릿 전송 → (숨김) `전송기록` 성공과 `RAW` 행 확인
6. 수동 동기화 후 비교결과·대시보드 확인

Apps Script 시간 기반 트리거는 정확히 03:00이 아니라 새벽 3시대에 실행될 수 있습니다. 필요할 때는 메뉴로 즉시 동기화할 수 있습니다.

## 개인정보 경계

- 이 파일은 관리자만 열람합니다. 학생과 공유하지 않습니다.
- 공개 GitHub/Vercel에는 학생명단·점수·원본 URL이 없습니다.
- 원본에서 중앙으로 저장되는 값은 학생 식별값과 항목별 집계뿐입니다.
- 원본 상세 열은 매핑식에 포함되지 않으면 읽지 않습니다.
- `OMS_STAGE` 기본 설정은 개인 상세가 있는 C·G열과 report 열 F·K를 건너뛰고 D:E·H:J 단계 열만 읽습니다.
- 원본 접근 권한, Apps Script 실행 승인, 웹 앱 배포는 로컬 코드가 대신 수행할 수 없으며 관리자 Google 계정에서 직접 해야 합니다.
