# Google Sheets 실제 설치 가이드

이 문서는 로컬에서 준비된 실제 명단 90명·실제 항목 206개를 Google Sheets와 북마클릿에 연결하는 순서입니다.

## 준비된 결과물

- `outputs/ufolio-score-system-20260806/01_유폴리오_사이트인증.xlsx`
- `outputs/ufolio-score-system-20260806/02_유폴리오_수기입력.xlsx`
- `outputs/ufolio-score-system-20260806/03_유폴리오_관리자.xlsx`
- `apps-script/Code.gs`
- `apps-script/SystemSetup.gs`

권장 경로는 ① 파일만 Google Sheets로 가져오고, Apps Script의 `createLinkedWorkbooks()`가 ②·③ 파일을 Google Drive에 새로 만들게 하는 방식입니다. ②·③ xlsx는 구조 확인과 비상 복구용입니다.

## 1. ① 사이트 인증 파일을 Google Sheets로 변환

1. 관리자 Google 계정의 Google Drive에 `01_유폴리오_사이트인증.xlsx`를 업로드합니다.
2. 업로드한 파일을 `Google 스프레드시트로 열기`로 엽니다.
3. `파일 → Google 스프레드시트로 저장`을 선택합니다.
4. 새 Google Sheets 파일은 학생에게 공유하지 않습니다.
5. `학생명단`에 헤더 제외 90명이 있고 `마스터항목`에 헤더 제외 206개가 있는지 확인합니다.

현재 실제 데이터에는 10개 과가 있습니다: 교정과, 구강내과, 구강병리과, 구강악안면외과, 보존과, 보철과, 소아치과, 영상치의학과, 원내생 진료센터, 치주과.

## 2. Apps Script 붙여넣기

1. ① 파일에서 `확장 프로그램 → Apps Script`를 엽니다.
2. 기본 `Code.gs` 내용을 모두 지우고 저장소의 `apps-script/Code.gs` 전체를 붙여넣습니다.
3. Apps Script 왼쪽 `+ → 스크립트`로 `SystemSetup` 파일을 만듭니다.
4. 저장소의 `apps-script/SystemSetup.gs` 전체를 붙여넣습니다.
5. 저장합니다.
6. 함수 목록에서 `createLinkedWorkbooks`를 선택해 한 번 실행합니다.
7. Google 권한 요청을 승인합니다. 경고 화면이 나오면 본인이 만든 스크립트인지 확인한 뒤 고급 메뉴에서 계속합니다.
8. 실행이 끝나면 ② 수기입력, ③ 관리자 파일 URL이 표시되고 ① 파일의 `설정` 시트에도 저장됩니다.

중복 생성을 막기 위해 `설정` 시트에 연결 파일 ID가 있으면 `createLinkedWorkbooks()`는 중단합니다.

## 3. 수기 대상 항목 결정

1. ① 파일 `마스터항목` 시트에서 실제로 수기로 받을 항목만 F열 `수기대상`을 `Y`로 바꿉니다.
2. G열 `비교기준`을 항목별로 `승인수`, `환자수`, `점수` 중 선택합니다.
3. `활성`은 북마클릿에서 받아도 되는 유폴리오 항목을 뜻합니다. 현재 실제 206개는 모두 `Y`입니다.
4. 스프레드시트를 새로고침하면 `유폴리오 관리` 메뉴가 나타납니다.
5. `유폴리오 관리 → 수기대상 열만 표시`를 실행합니다.

수기 대상이 확정되지 않아 현재 기본값은 모두 `N`, 비교기준은 `승인수`입니다. 임의로 추정해 공개 항목을 늘리지 않기 위한 설정입니다.

## 4. 학생별 편집 보호

1. ① 파일 `학생명단` D열에 각 학생의 Google 계정 이메일을 입력합니다.
2. `유폴리오 관리 → 명단을 수기입력 파일에 동기화`를 실행합니다.
3. `유폴리오 관리 → 학생별 행 보호 적용`을 실행합니다.
4. ② 파일을 학생 90명에게 편집자로 공유합니다.
5. ① 사이트 인증 파일과 ③ 관리자 파일은 공유하지 않습니다.

이메일이 하나라도 비어 있으면 보호 함수는 중단합니다. 행 보호는 실수 편집을 줄이지만, Google Sheets 편집자에게 보이는 수기값 자체를 비공개로 만들지는 않습니다.

## 5. 웹 앱 배포와 사이트 연결

1. Apps Script에서 `배포 → 새 배포`를 선택합니다.
2. 유형은 `웹 앱`, 실행 사용자는 `나`, 액세스 권한은 `모든 사용자`로 설정합니다.
3. 배포 권한을 승인합니다.
4. `/exec`로 끝나는 URL을 복사합니다.
5. 저장소 `config.js`의 `WEB_APP_URL`에 붙여넣습니다.
6. `npm.cmd test`를 실행합니다.
7. 새 GitHub 저장소에 이 브랜치를 푸시하고 Vercel에서 정적 사이트로 배포합니다.

웹 앱 코드를 바꾼 뒤에는 기존 배포의 새 버전을 만들어야 합니다. URL이 바뀌었으면 `config.js`도 바꾸고 Vercel을 다시 배포합니다.

## 6. 실제 통합 시험

1. Vercel 페이지에서 공통 북마클릿을 설치합니다.
2. 유폴리오에 로그인하고 임상실습요약표를 엽니다.
3. 북마클릿을 실행해 이름·학번이 자동 감지되는지 확인합니다.
4. 추출된 과와 항목 수를 화면과 비교하고 전송합니다.
5. ① 파일 `전송기록`에 `성공`, `RAW`에 같은 전송 ID의 행들이 생겼는지 확인합니다.
6. ① 파일에서 `유폴리오 관리 → 관리자 DB 지금 새로고침`을 실행합니다.
7. ③ 파일의 `사이트최신`, `수기DB`, `불일치`, `대시보드`를 확인합니다.
8. 정상 확인 후 `1시간 자동 새로고침 켜기`를 실행합니다.

북마클릿은 브라우저의 `no-cors` 방식으로 보내므로 화면의 “전송 요청 완료”만으로 저장 성공을 보증할 수 없습니다. 최종 성공은 반드시 `전송기록`에서 확인합니다.

## 7. 98~100번 학생 추가

1. 학번과 이름이 확정되면 ① 파일 `학생명단` 끝에 `출석번호 | 학번 | 이름 | 이메일` 순서로 추가합니다.
2. `명단을 수기입력 파일에 동기화`를 실행합니다.
3. `학생별 행 보호 적용`을 다시 실행합니다.
4. Apps Script 웹 앱이나 Vercel을 재배포할 필요는 없습니다.

## 보안상 정확한 한계

- 실제 명단과 사이트 점수는 공개 GitHub/Vercel에 포함되지 않습니다.
- 이름과 학번이 비공개 명단에 모두 일치하고, 전송 항목이 활성 마스터항목에 모두 존재해야 저장됩니다.
- 북마클릿은 비밀번호·세션 쿠키·인증 토큰을 전송하지 않습니다.
- 그러나 공개 웹 앱 URL로 들어오는 요청이 실제 유폴리오 세션에서 생성됐는지를 암호학적으로 증명할 방법은 없습니다. 클라이언트 요청을 직접 조작하는 공격까지 완전히 막는 구조는 아닙니다.
- 유폴리오가 서명 토큰이나 서버 검증 API를 제공하지 않는 한 이 한계는 남습니다. 따라서 `전송기록`, 최신값 규칙, 마스터항목 검증으로 이상 전송을 추적합니다.
