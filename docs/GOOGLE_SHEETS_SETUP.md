# Google Sheets 실제 설치·운영 가이드

이 가이드는 기존 케이스장 시트를 변경하지 않고, 학생 93명·U-FOLIO 마스터 206개를 관리자 전용 비교 시스템에 연결하는 순서입니다.

## 준비된 결과물

- `outputs/ufolio-case-integration-20260806/01_유폴리오_사이트인증.xlsx`
- `outputs/ufolio-case-integration-20260806/02_유폴리오_통합관리자.xlsx`
- `apps-script/Code.gs`
- `apps-script/CaseSheetCore.gs`
- `apps-script/CaseSheetDefaults.gs`
- `apps-script/CaseSheetSync.gs`
- `apps-script/SystemSetup.gs`

권장 운영 경로는 ① xlsx를 Google Sheets로 변환하고 `createIntegrationAdminWorkbook()`으로 새 ② Google Sheets를 만드는 방식입니다. 제공된 ② xlsx는 구조 확인·비상 복구용입니다.

## 1. ① 사이트 인증 파일 준비

1. 관리자 Google Drive에 `01_유폴리오_사이트인증.xlsx`를 업로드합니다.
2. `Google 스프레드시트로 열기` 후 `파일 → Google 스프레드시트로 저장`을 선택합니다.
3. 제목 옆의 `.XLSX` 표시가 사라지고 새 Google Sheets URL이 열린 것을 확인합니다. 원본 Excel 편집 화면에서는 Apps Script 초기화가 권한 오류로 중단됩니다.
4. 학생과 공유하지 않습니다.
5. `학생명단`이 헤더 제외 93행인지 확인합니다.
6. `마스터항목`이 헤더 제외 206행인지 확인합니다.

## 2. Apps Script 5개 파일 붙여넣기

1. ① 파일에서 `확장 프로그램 → Apps Script`를 엽니다.
2. 기본 `Code.gs`를 저장소의 `apps-script/Code.gs` 전체 내용으로 교체합니다.
3. 왼쪽 `+ → 스크립트`로 아래 파일을 각각 만들고 같은 이름의 저장소 파일 전체 내용을 붙여넣습니다.

   - `CaseSheetCore`
   - `CaseSheetDefaults`
   - `CaseSheetSync`
   - `SystemSetup`

4. 저장합니다.
5. 함수 목록에서 `createIntegrationAdminWorkbook`을 실행합니다.
6. Google 권한 요청을 승인합니다.
7. 생성된 ② URL이 표시되고 ① `설정`에 `ADMIN_SPREADSHEET_ID`와 `ADMIN_SPREADSHEET_URL`이 생겼는지 확인합니다.

이미 ID가 있으면 중복 생성을 막기 위해 함수가 중단됩니다.

## 3. 11개 원본을 뷰어로 공유

현재 기본 소스는 논리적으로 11개입니다. 발치·임플란트가 한 파일의 서로 다른 탭이므로 실제 원본 파일은 10개입니다.

1. Apps Script를 실행한 관리자 Google 계정을 각 원본 Google Sheets의 `뷰어`로 추가합니다.
2. 원본 링크를 복사합니다.
3. ② `현황시트연결` E열 `스프레드시트 URL`의 해당 소스 행에 붙여넣습니다.
4. 파일명 대신 `소스키`와 `시트명`을 보고 맞는 행에 넣습니다.
5. 원본 시트의 셀·수식·탭명은 수정하지 않습니다.

URL이 들어가야 하는 소스키:

- `CONS_SCORE`, `CONS_SURGERY`
- `PED_CHART`
- `PERIO`
- `OM`
- `EXT`, `IMPLANT`
- `PATH`
- `PROS`
- `OMS`
- `OMS_STAGE`

같은 파일을 사용하는 두 소스 행에는 같은 URL을 넣습니다.

### `setFrozenRows` 권한 오류가 발생할 때

`createIntegrationAdminWorkbook()` 실행 중 `You do not have permission to call setFrozenRows`가 나오면 새 관리자 파일 문제가 아니라 ① 파일 초기화가 중단된 것입니다.

1. ① 파일 제목 옆에 `.XLSX` 표시가 있는지 확인합니다.
2. 표시가 있으면 `파일 → Google 스프레드시트로 저장`을 실행합니다.
3. 새로 열린 Google Sheets 파일에서 Apps Script 5개 파일을 다시 붙여넣고 함수를 실행합니다.
4. 이미 Google Sheets 형식이라면 공유 설정에서 현재 실행 계정이 `편집자` 또는 소유자인지 확인하고, Apps Script의 권한 요청을 모두 승인합니다.

이 오류는 관리자 파일을 만들기 전에 발생하므로 실패한 실행으로 생성된 ② 파일은 없습니다.

## 4. 연결 검사

1. ① 파일을 새로고침합니다.
2. `유폴리오 통합관리 → 현황시트 연결 검사`를 실행합니다.
3. ② `현황시트연결` N열 상태와 O열 오류를 확인합니다.
4. 문제가 있으면 ② `연결진단`에서 상세를 확인합니다.

연결 오류는 대개 다음 중 하나입니다.

- URL이 비어 있거나 Google Sheets URL 형식이 아님
- 관리자 계정에 뷰어 권한이 없음
- 원본 탭명이 바뀜
- 설정한 열이나 시작행이 실제 구조와 달라짐

## 5. 초기 매핑 검토

② `항목매핑`에는 53개 초기 매핑이 들어 있습니다.

- `승인`: 구조와 의미가 비교적 명확해 비교에 포함됨
- `검토필요`: 의미·인증 시점이 애매해 통계에서 제외됨
- `보류`: 사용하지 않기로 결정한 매핑

병리 단계, 보철 집계점수, 임플란트 A/O 구분, Biopsy·I&D 단계 인증은 기본적으로 `검토필요`입니다. 실제 운영 규칙을 확인한 행만 C열을 `승인`으로 바꿉니다. 확실하지 않은 행을 임의 승인하지 않습니다.

제한 집계식:

- `VALUE(C)`: C열 숫자, 공란은 공란
- `NUMBER_OR_ZERO(C)`: C열 공란을 0으로 변환
- `NONEMPTY_AS_ONE(C)`: 값이 있으면 1
- `SUM(C,D)`: 지정 열의 숫자 합
- `COUNT_NONEMPTY(E:H)`: 범위에서 비어 있지 않은 셀 수
- `COUNT_STATUS(E:V,완)`: 범위에서 `완`과 정확히 같은 셀 수

## 6. 첫 동기화와 결과 확인

1. `유폴리오 통합관리 → 지금 전체 동기화`를 실행합니다.
2. ② `현황최신`에서 학생별 집계값이 생성됐는지 확인합니다.
3. ② `유폴리오최신`에서 각 항목의 최신 제출만 남았는지 확인합니다.
4. ② `비교결과`에서 `일치`, `반영대기`, `현황누락의심`, `유폴리오미인증`을 표본 학생 몇 명으로 대조합니다.
5. ② `연결진단`과 `동기화로그`에 예상하지 못한 오류가 없는지 확인합니다.
6. 이상이 없으면 `매일 새벽 3시 동기화 켜기`를 실행합니다.

Apps Script 시간 기반 트리거는 정확히 03:00이 아니라 새벽 3시대에 실행될 수 있습니다. 필요할 때는 메뉴로 즉시 동기화할 수 있습니다.

## 7. 상태별 조치

| 상태 | 확인할 것 |
|---|---|
| `일치` | 조치 없음 |
| `반영대기` | 아직 U-FOLIO 사인·반영 전인지 확인 |
| `현황누락의심` | 원본 현황 집계나 우선순위 매핑 확인 |
| `유폴리오미인증` | 학생이 최근 U-FOLIO 제출을 했는지 확인 |
| `매핑대기` | 해당 매핑의 의미를 확인하고 승인·보류 결정 |
| `원본오류` | URL, 권한, 탭, 열, 수식 오류 확인 |
| `학생불일치` | 출석번호와 이름이 ① 학생명단과 같은지 확인 |
| `원본노후` | 이번 동기화가 실패함. 복구 전까지 마지막 정상값 사용 중 |

원본 탭이나 열이 바뀌었을 때는 ② 설정 행만 수정하고 다시 연결 검사·동기화합니다. 마지막 정상값을 지우지 않아도 됩니다.

## 8. 새 현황시트 추가

### 원본 무수정 방식

1. ② `현황시트연결`에 새 소스키와 URL·탭·열·시작행을 추가합니다.
2. ② `항목매핑`에 해당 소스키, 집계식, U-FOLIO 대상, 측정값, 우선순위를 추가합니다.
3. 검토상태는 `검토필요`로 시작합니다.
4. 연결 검사와 수동 동기화 후 값이 맞을 때만 `승인`합니다.

### `_UFOLIO_EXPORT` 예외

원본 구조가 병합 셀·환자별 반복 블록 때문에 안전하게 집계하기 어려운 경우에만 케이스장과 합의해 숨김 `_UFOLIO_EXPORT` 탭을 추가할 수 있습니다.

표준 열:

| 열 | 내용 |
|---|---|
| A | 출석번호 |
| B | 이름 |
| C | 완료 집계 |
| D | 예정 집계 |
| E | 인증대상 집계 |

환자 이름·번호, 담당자, 날짜, 상세 메모는 이 탭에 포함하지 않습니다. 어댑터를 `_UFOLIO_EXPORT`로 선택하고 탭명과 집계식을 맞춥니다.

## 9. 웹 앱 배포와 북마클릿 시험

1. Apps Script `배포 → 새 배포`
2. 유형 `웹 앱`
3. 실행 사용자 `나`
4. 액세스 `모든 사용자`
5. `/exec` URL을 저장소 `config.js`의 `WEB_APP_URL`에 입력
6. `npm.cmd test`
7. GitHub main 푸시 후 Vercel 재배포
8. 표본 학생 계정에서 북마클릿 전송
9. ① `전송기록` 성공과 `RAW` 행 확인
10. 통합 수동 동기화 후 ② 비교 결과 확인

## 10. 기존 별도 입력 파일 정리

새 ② 통합 관리자 파일의 연결 검사·첫 동기화·표본 비교가 모두 정상인 뒤, 기존 Google Drive의 별도 입력 파일은 삭제하거나 휴지통으로 이동합니다. 케이스장 원본과 ① 사이트 인증 파일은 삭제하지 않습니다.

## 개인정보 경계

- ①과 ②는 관리자만 열람합니다.
- 공개 GitHub/Vercel에는 학생명단·점수·원본 URL이 없습니다.
- 원본에서 중앙으로 저장되는 값은 학생 식별값과 항목별 집계뿐입니다.
- 원본 상세 열은 매핑식에 포함되지 않으면 읽지 않습니다.
- `OMS_STAGE` 기본 설정은 개인 상세가 있는 C·G열을 건너뛰고 D:F·H:K 집계 열만 읽습니다.
- 원본 접근 권한, Apps Script 실행 승인, 웹 앱 배포는 로컬 코드가 대신 수행할 수 없으며 관리자 Google 계정에서 직접 해야 합니다.
