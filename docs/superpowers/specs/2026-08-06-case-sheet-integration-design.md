# 케이스장 현황 시트 연동 설계

## 1. 목표

기존 케이스장 Google Sheets의 입력 방식과 서식을 그대로 유지하면서, 학생이 북마클릿으로 보낸 U-FOLIO 전체 항목 최신값과 케이스장 현황의 인증대상 값을 중앙 관리자 파일에서 비교한다.

이전 설계의 `② 유폴리오 수기입력` 파일은 제거한다. 학생과 케이스장은 새 입력 파일을 사용하지 않는다. 케이스장은 기존 현황 시트를 계속 관리하고, 학생은 월 1회 정도 U-FOLIO 전체 점수를 전송한다.

## 2. 승인된 운영 원칙

- 관리자 Google 계정은 모든 원본 현황 시트에 뷰어 권한을 가진다.
- 원본 현황 시트는 기본적으로 수정하지 않는다.
- 직접 해석이 불안정한 시트만 운영자 승인 아래 숨김 `_UFOLIO_EXPORT` 탭을 추가할 수 있다.
- 학생은 출석번호로 연결하고 이름까지 교차 검증한다. 불일치 행은 제외하고 오류로 기록한다.
- 중앙 파일에는 학생별 집계값만 저장한다. 환자 이름, 환자번호, 담당자, 세부 메모는 저장하지 않는다.
- U-FOLIO는 현재 206개 전체 항목을 수신한다. 비교는 승인된 매핑이 있는 항목 또는 항목 묶음만 수행한다.
- 수동 동기화 메뉴와 매일 새벽 3시 자동 동기화를 제공한다.
- 한 원본이 실패해도 다른 원본은 계속 동기화한다. 실패한 원본의 마지막 정상 스냅샷은 유지한다.
- 앞으로 현황 시트가 추가될 수 있으므로 연결과 매핑은 시트 데이터로 관리한다.

원본 내과 파일에는 일부 총점 수식의 `#REF!` 오류가 실제로 존재한다. 중앙 시스템은 해당 총점 열을 비교 근거로 사용하지 않고, 승인된 원시 항목 열에서 필요한 집계값을 다시 계산한다. 선택된 원시 범위에서도 수식 오류가 발견되면 해당 매핑을 `원본오류`로 처리한다.

## 4. 선택한 접근

### 4.1 선택안: 중앙 Apps Script 직접 읽기 + 설정 기반 어댑터

① 사이트 인증 파일에 바인딩된 Apps Script가 관리자 계정 권한으로 원본 파일을 읽는다. 원본마다 코드를 새로 작성하는 대신 관리자 파일의 `현황시트연결`과 `항목매핑`을 읽어 제한된 집계식을 실행한다.

장점:

- 원본 시트와 케이스장 업무 흐름을 바꾸지 않는다.
- 환자 단위 값을 중앙 시트에 복사하지 않는다.
- 새 현황 시트는 연결·매핑 행 추가만으로 대부분 지원한다.
- 소스별 실패 격리, 마지막 정상값 유지, 구조 변경 감지가 가능하다.

### 4.2 제외안: IMPORTRANGE 중심 통합

다단 헤더, 숨김 열, 넓은 환자별 기록, 여러 파일의 권한 승인 때문에 구조가 취약하다. 환자 단위 데이터가 중앙 파일에 그대로 노출될 위험도 있어 사용하지 않는다.

### 4.3 보조안: `_UFOLIO_EXPORT` 표준 탭

직접 해석이 지나치게 불안정한 원본에만 사용한다. 표준 열은 `출석번호, 이름, 과, 현황항목, 완료값, 예정값, 인증대상값, 기준시각`이다. 기존 입력 탭은 수정하지 않고 숨김 탭의 수식만 추가한다.

## 5. 파일 구성

### 5.1 ① 유폴리오 사이트 인증

유지되는 시트:

- `사용안내`
- `설정`
- `학생명단`
- `마스터항목`
- `RAW`
- `전송기록`

역할:

- 북마클릿 POST 수신
- 학번·이름·활성 마스터항목 검증
- U-FOLIO 전체 항목 누적 저장
- 통합 관리자 파일 ID 저장
- 동기화 메뉴와 시간 기반 트리거의 실행 위치

### 5.2 ② 유폴리오 통합 관리자

- `사용안내`: 최초 설치와 운영 순서
- `대시보드`: 핵심 상태 수와 과별 현황
- `현황시트연결`: 원본 URL·탭·키 열·행 범위·우선순위·상태
- `항목매핑`: 원본 집계식과 U-FOLIO 대상 연결
- `현황최신`: 마지막 정상 학생별 집계 스냅샷
- `유폴리오최신`: 마지막 전송 기준 U-FOLIO 값
- `비교결과`: 모든 승인 매핑의 비교 결과
- `미매핑항목`: 현재 매핑되지 않은 U-FOLIO 항목
- `연결진단`: 접근권한·탭·헤더·학생명단·수식 오류
- `동기화로그`: 실행별 성공·실패·보존 여부
- `마스터항목`: ①의 최신 사본

별도 학생용 또는 수기입력용 파일은 만들지 않는다.

## 6. 설정 스키마

### 6.1 `현황시트연결`

| 열 | 의미 |
|---|---|
| 소스키 | 매핑에서 참조하는 영구 식별자 |
| 활성 | Y/N |
| 과 | 원본 담당 과 |
| 표시명 | 관리자 화면 이름 |
| 스프레드시트 URL | 운영자가 붙여넣는 Google Sheets URL |
| 탭명 | 읽을 탭 |
| 출석번호열 | A1 열 문자 |
| 이름열 | A1 열 문자 |
| 첫데이터행 | 학생 데이터 시작 행 |
| 마지막데이터행 | 비우면 출석번호 연속 영역을 자동 탐지 |
| 우선순위 | 같은 항목을 여러 소스가 제공할 때 낮은 수가 우선 |
| 어댑터 | `CONFIG`, `EXPORT_TAB` 중 하나 |
| 마지막성공 | 시스템 기록 |
| 상태 | 시스템 기록 |
| 오류 | 시스템 기록 |

스프레드시트 URL은 로컬 생성물에서는 비워 둔다. 운영자가 Google Sheets 전환 후 붙여넣는다. 파일명·탭·열·행·우선순위 기본값은 미리 제공한다.

### 6.2 `항목매핑`

| 열 | 의미 |
|---|---|
| 매핑키 | 영구 식별자 |
| 활성 | Y/N |
| 검토상태 | `승인`, `검토필요`, `보류` |
| 소스키 | 현황시트연결 참조 |
| 현황표시명 | 관리자용 이름 |
| 완료식 | 완료값 집계식 |
| 예정식 | 예정값 집계식 |
| 인증대상식 | U-FOLIO와 비교할 값 집계식 |
| U-FOLIO 실습차수 | 원본 키 |
| U-FOLIO 과 | 원본 키 |
| U-FOLIO 메뉴 | 원본 키 |
| U-FOLIO 항목목록 | `||`로 구분한 하나 이상의 항목 |
| U-FOLIO 측정값 | `승인수`, `환자수`, `점수` |
| U-FOLIO 집계 | `단일`, `합계` |
| 비고 | 매핑 근거와 운영자 확인 사항 |

`검토상태=승인`인 행만 비교한다. 자동 매핑이 확실하지 않은 행은 기본적으로 `검토필요`이며 대시보드에 표시하되 불일치 통계에는 포함하지 않는다.

## 7. 제한된 집계식

자유로운 JavaScript나 시트 수식을 실행하지 않는다. 다음 형식만 허용한다.

- `VALUE(C)`: 현재 학생 행 C열 숫자
- `SUM(C,D)`: 현재 학생 행의 지정 열 합계
- `COUNT_NONEMPTY(E:AH)`: 지정 범위에서 비어 있지 않은 셀 수
- `COUNT_STATUS(E:V,완)`: 지정 범위에서 상태가 `완`인 셀 수
- `NONEMPTY_AS_ONE(C)`: 값이 있으면 1, 없으면 0
- `NUMBER_OR_ZERO(C)`: 숫자가 아니면 0

완료식과 예정식은 별도로 계산한다. 인증대상식은 보통 누적 열 또는 `완료+예정`을 사용한다. 소스 값이 음수, 무한대, 수식 오류, 허용되지 않은 문자열이면 해당 학생·매핑을 오류로 기록한다.

## 8. U-FOLIO 비교

U-FOLIO 최신값 키는 기존과 동일하게 `(학번, 실습차수, 과, 메뉴, 항목)`을 사용한다. 한 매핑이 여러 U-FOLIO 항목을 대상으로 하면 측정값을 합산한다.

판정:

- `일치`: 인증대상값과 U-FOLIO 값이 수치상 동일
- `반영대기`: 인증대상값이 U-FOLIO 값보다 큼
- `현황누락의심`: U-FOLIO 값이 인증대상값보다 큼
- `유폴리오미인증`: 현황값은 있으나 대상 U-FOLIO 최신값이 전혀 없음
- `매핑대기`: 검토상태가 승인이 아님
- `원본오류`: 권한·탭·구조·수식·값 오류
- `학생불일치`: 출석번호가 없거나 이름이 학생명단과 다름
- `원본노후`: 동기화 실패로 마지막 정상 스냅샷을 사용 중

0과 빈 값은 구분한다. 소수점은 허용하며 `3`, `3.0`은 동일하게 비교한다.

## 9. 동기화와 장애 격리

1. 관리자가 `현황+U-FOLIO 지금 동기화`를 실행하거나 새벽 3시 트리거가 실행된다.
2. 각 활성 소스를 별도 `try/catch`와 별도 결과 버퍼로 읽는다.
3. 성공한 소스만 해당 소스의 `현황최신` 행을 교체한다.
4. 실패한 소스는 기존 정상 행을 유지하고 `원본노후`로 표시한다.
5. U-FOLIO RAW에서 항목별 마지막 전송값을 만든다.
6. 승인 매핑을 비교하고 미승인 매핑과 미매핑 항목을 별도 출력한다.
7. 진단과 실행 요약을 `동기화로그`에 추가한다.

메뉴:

- `② 통합 관리자 최초 생성`
- `현황 연결 검사`
- `현황+U-FOLIO 지금 동기화`
- `매일 새벽 3시 자동 동기화 켜기`
- `자동 동기화 끄기`

Apps Script 시간 기반 트리거는 지정 시각 내 임의 시점에 실행될 수 있으므로 사용자 안내에는 `새벽 3시대`로 표현한다.

## 10. 원본별 초기 매핑 정책

- 헤더와 U-FOLIO 항목이 직접 대응하고 단위가 분명한 항목은 `승인`으로 시드한다.
- 승인수·환자수·점수가 혼합된 구강내과는 열 설명에 따라 측정값을 분리한다.
- 발치·외과의 전문 현황과 종합 현황이 중복되는 항목은 전문 현황의 우선순위를 높인다.
- 치주의 `OE+SC+PCI`처럼 묶인 값은 여러 U-FOLIO 항목의 합계와 비교한다.
- 보철의 집계 점수와 병리의 단계 표시는 U-FOLIO 항목 의미가 확정되지 않은 경우 `검토필요`로 시드한다.
- Biopsy/I&D 단계 파일은 환자정보를 저장하지 않고 단계 완료 개수만 계산한다. U-FOLIO 인정 시점이 불명확한 단계는 `검토필요`로 둔다.

## 11. 개인정보와 공개 저장소 경계

- `현황시트 모음/`, 실제 학생명단, 생성된 운영 xlsx, 구조 검사 결과는 Git에서 제외한다.
- 공개 저장소에는 파일명·탭명·열 구조·집계 규칙만 포함할 수 있다.
- 중앙 파일에는 출석번호, 학번, 학생 이름, 과, 현황항목, 집계값, 비교 결과, 원본 링크만 저장한다.
- 환자 이름·번호·날짜·담당자·메모는 중앙 파일에 쓰지 않는다.
- 원본 URL은 운영자가 Google Sheets에서 입력하며 공개 Git에 포함하지 않는다.

## 12. 테스트와 검증

- 제한 집계식 파서의 정상·오류·0·소수점 테스트
- 출석번호 연결과 이름 불일치 테스트
- 소스별 실패 격리와 마지막 정상 스냅샷 보존 테스트
- 단일/복수 U-FOLIO 항목 합산 비교 테스트
- 상태 판정 전체 분기 테스트
- 미승인 매핑이 불일치 통계에 들어가지 않는지 테스트
- 실제 원본에서 개인정보를 제거한 구조 fixture로 11개 연결 기본값 테스트
- 생성 xlsx의 핵심 범위와 수식 오류 검사
- 생성 xlsx의 모든 시트 렌더링과 육안 검증
- 전체 Node 테스트 실행

## 13. 사용자에게 남는 작업

코드와 xlsx가 완성된 뒤 사용자만 수행할 작업은 다음으로 제한한다.

1. 새 ① 파일을 Google Sheets로 변환한다.
2. Apps Script 코드 파일을 붙여넣고 권한을 승인한다.
3. `② 통합 관리자 최초 생성`을 실행한다.
4. 관리자 파일 `현황시트연결`에 실제 Google Sheets URL을 붙여넣는다.
5. 각 원본을 Apps Script 실행 관리자 계정에 뷰어로 공유한다.
6. `현황 연결 검사` 후 `현황+U-FOLIO 지금 동기화`를 실행한다.
7. `검토필요` 매핑을 확인해 승인 또는 보류한다.
8. 웹 앱 URL을 발급해 정적 사이트에 연결하고 실제 계정으로 통합 시험한다.

원본 Google Sheets URL과 Apps Script 배포 URL은 외부 계정 상태이므로 로컬 구현물에 하드코딩하지 않는다.
