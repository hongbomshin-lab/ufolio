# 유폴리오 점수 수집기 독립 프로젝트 설계

## 1. 목적

기존 달신 웹사이트에서 유폴리오 점수 수집 기능만 분리해 새로운 GitHub 저장소와 Vercel 프로젝트로 배포한다. 사용자는 자체 회원가입이나 로그인 없이 동일한 북마클릿을 설치한다. 북마클릿은 사용자가 이미 로그인한 u-folio 세션에서 본인 식별 정보와 임상실습 점수를 읽어 관리자 소유 Google Spreadsheet로 전송한다.

이 저장소는 다음 두 기능만 제공한다.

1. 누구나 접속할 수 있는 공통 북마클릿 설치 페이지
2. 관리자 전용 Spreadsheet에 점수를 적재하는 Apps Script 수신 코드

## 2. 범위

### 포함

- 프레임워크 없는 정적 설치 페이지
- 모든 학생이 공유하는 단일 북마클릿
- u-folio 화면의 `이름(학번)` 형식 로그인 정보 자동 추출
- 기존 u-folio 내부 API를 이용한 차수, 과, 메뉴, 항목 및 세 가지 값 추출
- 비공개 학생명단의 학번과 이름 검증 및 출석번호 매핑
- 항목별 원본 데이터 누적 저장
- 전송 단위 감사 기록
- 새 GitHub 저장소 및 새 Vercel 프로젝트용 배포 문서

### 제외

- 기존 달신 자체 회원가입, 로그인 및 관리자 승인
- Supabase와 모든 데이터베이스 마이그레이션
- 달신 신청, 달력, 장부, 알림, OCS 및 관리자 기능
- 수기입력 파일, 통계 파일, 불일치 비교 파일 자체의 생성과 운영
- 학생별 점수 조회 웹페이지
- u-folio 비밀번호 또는 세션 쿠키의 수집과 저장

수기입력·통계·불일치 비교는 별도 Spreadsheet 프로젝트가 담당한다. 이 저장소는 비교 가능한 사이트 원본값을 수집하는 역할만 한다.

## 3. 최종 저장소 구조

```text
/
├─ index.html
├─ styles.css
├─ config.js
├─ bookmarklet.js
├─ site.js
├─ vercel.json
├─ package.json
├─ README.md
├─ apps-script/
│  ├─ Code.gs
│  └─ README.md
├─ tests/
│  └─ bookmarklet.test.mjs
└─ docs/
   └─ superpowers/
      └─ specs/
         └─ 2026-08-06-ufolio-standalone-design.md
```

- 사이트는 정적 파일만 사용하며 Next.js, React, 빌드 산출물 및 런타임 서버가 없다.
- `config.js` 한 곳에 Apps Script 웹앱 URL을 설정한다. URL은 쓰기 엔드포인트이지만 비밀로 간주하지 않는다.
- `bookmarklet.js`는 설치 페이지와 Node 내장 테스트에서 함께 사용할 수 있는 순수 로직과 북마클릿 생성기를 제공한다.
- `package.json`에는 외부 의존성 없이 Node 내장 테스트 실행 명령만 둔다.
- 과거 달신 Git 이력이 새 GitHub 저장소에 들어가지 않도록 최종 결과는 새 루트 커밋에서 시작한다.

## 4. 데이터 흐름

1. 사용자가 새 Vercel 설치 페이지를 연다.
2. 페이지는 `config.js`의 Apps Script URL을 넣은 공통 북마클릿 링크를 만든다.
3. 사용자가 링크를 즐겨찾기 바로 드래그해 설치한다.
4. 사용자가 `sdent.u-folio.com`에 로그인하고 임상실습요약표를 연다.
5. 북마클릿이 화면 상단 사용자 영역에서 `홍길동(2024-12345)`과 같은 텍스트를 찾아 이름과 학번을 분리한다.
6. 북마클릿이 u-folio same-origin 요청으로 `/ajax/st/dent_summary/list`를 호출해 가능한 실습차수를 표시한다.
7. 사용자가 차수를 선택하면 `/ajax/st/dent_summary/getSummaryData`를 호출해 모든 과와 항목을 수집한다.
8. 수집 결과를 북마클릿 패널에서 확인한 뒤 Apps Script에 한 번의 JSON 요청으로 전송한다.
9. Apps Script가 비공개 `학생명단` 시트에서 학번을 조회하고 이름까지 일치하는지 확인한다.
10. 검증 성공 시 출석번호를 붙여 `RAW`에 항목별 행을 일괄 추가하고 `전송기록`에 성공 기록을 남긴다.
11. 검증 실패 시 점수는 저장하지 않고 `전송기록`에 거부 사유를 남긴다.

## 5. 북마클릿 설계

### 5.1 동일한 설치물

북마클릿에는 달신 계정이나 학생별 식별자를 주입하지 않는다. 모든 사용자가 같은 `javascript:` URL을 설치한다. 개인 식별 정보는 실행 시점에 현재 u-folio 페이지에서만 읽는다.

### 5.2 본인 식별

- 우선순위가 높은 상단 사용자 영역 셀렉터에서 텍스트를 찾는다.
- 텍스트는 `이름(YYYY-NNNNN)` 패턴으로 파싱한다.
- 이름의 앞뒤 공백은 제거하고 학번은 `4자리-5자리` 형식으로 정규화한다.
- 선택 영역에서 찾지 못할 때에만 헤더 범위의 제한된 대체 탐색을 수행한다.
- 전체 문서 본문에서 무차별 검색하지 않는다. 다른 학생 학번이나 예시 문구를 잘못 잡는 일을 방지하기 위함이다.
- 이름이나 학번을 확실하게 하나로 결정하지 못하면 전송하지 않는다.

### 5.3 점수 추출

기존에 동작하던 u-folio 내부 API를 유지한다.

- 과목 목록: `POST /ajax/st/dent_summary/list`
- 항목 상세: `POST /ajax/st/dent_summary/getSummaryData`
- 인증: 현재 브라우저의 u-folio same-origin 세션만 사용
- 비밀번호, 쿠키, 토큰은 전송 페이로드에 포함하지 않음

각 항목에서 다음 값을 보존한다.

- 실습차수: `curr_name`
- 과: `dt_name`
- 메뉴/구분: `menu_name`
- 항목: `pc_name`
- 승인 수: `app_cnt`
- 환자 수: `sum_patient_cnt`
- 점수: `cal_score`
- 점수 원문: 점수 미설정 여부를 포함한 표시값

과목 수를 8개로 하드코딩하지 않는다. u-folio가 반환한 모든 과와 항목을 수집하며, 후속 비교 시스템이 `마스터항목` 기준으로 필요한 행을 선택한다.

### 5.4 전송 페이로드

```json
{
  "schemaVersion": 1,
  "submissionId": "브라우저에서 생성한 UUID",
  "clientSentAt": "ISO-8601 시각",
  "student": {
    "studentId": "2024-12345",
    "name": "홍길동"
  },
  "practices": ["3학년 치의학 임상실습 2"],
  "items": [
    {
      "practiceName": "3학년 치의학 임상실습 2",
      "departmentName": "교정과",
      "menuName": "증례별 임상참여",
      "itemName": "Assist case - Etc.",
      "approvedCount": 2,
      "patientCount": 2,
      "score": 82,
      "scoreRaw": "82"
    }
  ]
}
```

## 6. Spreadsheet 및 Apps Script 설계

### 6.1 `학생명단` 시트

관리자 전용 Spreadsheet 안에 두며 공개 저장소에 명단을 커밋하지 않는다.

| A | B | C |
|---|---|---|
| 출석번호 | 학번 | 이름 |

- 학번을 유일키로 사용한다.
- 같은 이름의 학생이 있어도 학번으로 구분한다.
- 이름은 공백을 정규화한 뒤 명단과 대조한다.
- 현재 누락된 번호나 추후 확정될 98~100번은 시트에 행을 추가하면 코드 변경 없이 인식한다.
- 명단에 없는 학번과 이름 불일치는 모두 거부한다.

### 6.2 `RAW` 시트

한 항목을 한 행에 저장하면서 u-folio의 세 가지 숫자 값을 각각 보존한다.

| 열 | 내용 |
|---|---|
| A | 수신시각 |
| B | 전송 ID |
| C | 출석번호 |
| D | 학번 |
| E | 이름 |
| F | 실습차수 |
| G | 과 |
| H | 메뉴/구분 |
| I | 항목 |
| J | 승인 수 |
| K | 환자 수 |
| L | 점수 |
| M | 점수 원문 |

- `미설정` 점수는 L열을 비우고 M열에 `미설정`을 저장한다.
- 0은 빈 값과 구분해 숫자 0으로 저장한다.
- 소수점 점수를 보존한다.
- 여러 과와 항목은 각각 별도 행으로 저장한다.
- 동일 학생의 재전송은 기존 행을 삭제하지 않고 새 전송 ID와 수신시각으로 누적한다.
- 후속 최신값 추출 키는 `(출석번호, 실습차수, 과, 메뉴, 항목)`이며 가장 최근 수신시각의 행을 사용한다.

### 6.3 `전송기록` 시트

| 열 | 내용 |
|---|---|
| A | 수신시각 |
| B | 전송 ID |
| C | 출석번호 |
| D | 학번 |
| E | 이름 |
| F | 항목 수 |
| G | 상태 |
| H | 상세 사유 |

- 성공, 거부, 파싱 실패를 구분한다.
- 거부 요청의 점수 항목은 `RAW`에 저장하지 않는다.
- 항목 수와 전송 ID로 중복·비정상 전송을 추적한다.

### 6.4 수신 처리

- `doPost(e)`는 `text/plain` 요청 본문의 JSON을 파싱한다.
- 스키마 버전, 필수 필드, 문자열 길이, 숫자 형식 및 최대 항목 수를 검증한다.
- 학생명단을 학번 기준 맵으로 만들고 이름을 함께 대조한다.
- `LockService`를 사용해 동시 행 추가 충돌을 방지한다.
- 검증된 행 배열을 한 번의 `setValues`로 기록한다.
- 사용자 제공 문자열은 수식으로 실행되지 않게 spreadsheet formula injection을 무력화한다.
- 초기 헤더와 필수 시트를 만드는 관리자 실행용 설정 함수를 제공한다.

## 7. 사용자 인터페이스

설치 페이지에는 다음만 둔다.

- 서비스 제목과 한 문장 설명
- 공통 북마클릿 드래그 설치 버튼
- 수동 등록용 코드 복사 UI
- 유폴리오 로그인 및 임상실습요약표 이동 링크
- 실행 순서
- 개인정보 처리 및 보안 한계 안내
- Apps Script URL 미설정 시 배포 관리자에게만 보이는 명확한 설정 오류

북마클릿 패널에는 다음을 둔다.

- 자동 감지된 이름과 학번
- 실습차수 선택
- 추출 진행률
- 추출된 과·항목 수
- 점수 있는 항목 기본 보기와 전체 항목 토글
- 전송 버튼과 다시 전송 버튼
- 닫기 버튼

Apps Script 요청은 `mode: "no-cors"`를 사용하므로 브라우저는 서버 응답 본문과 상태를 읽을 수 없다. 따라서 UI는 `저장 성공`이라고 표시하지 않고 `전송 요청 완료 - 관리자 전송기록에서 확인`이라고 정확히 표시한다.

## 8. 오류 처리

| 상황 | 처리 |
|---|---|
| u-folio가 아닌 사이트에서 실행 | 즉시 중단하고 올바른 사이트 안내 |
| 로그인 정보 미검출 또는 여러 후보 | 전송 금지, 재로그인·페이지 확인 안내 |
| 로그인 세션 만료 | 내부 API 응답 오류를 표시하고 전송 금지 |
| 과목 목록 0개 | 임상실습요약표 위치 확인 안내 |
| 일부 과목 상세 호출 실패 | 실패 과목을 표시하고 전체 자동 전송 금지 |
| 항목 0개 | 전송 금지 |
| 학번 미등록 | Apps Script에서 거부 기록 |
| 이름 불일치 | Apps Script에서 거부 기록 |
| 잘못된 숫자·과도한 항목 수 | Apps Script에서 거부 기록 |
| 동시 전송 | `LockService`로 직렬화 |
| 재전송 | 새 전송으로 누적 저장 |
| Apps Script 네트워크 요청 자체 실패 | 브라우저에서 실패 안내 |

## 9. 개인정보와 보안 경계

- 학생명단과 점수 Spreadsheet는 관리자만 소유하며 학생과 공유하지 않는다.
- 공개 GitHub에는 실제 학생명단, 학번, 이름, 점수 샘플을 넣지 않는다. 문서 예시는 사용자가 제공한 화면 형식 설명에 필요한 최소 예시만 사용한다.
- 북마클릿은 u-folio 비밀번호, 세션 쿠키, 인증 토큰을 읽거나 외부로 보내지 않는다.
- Vercel 페이지에는 개인별 정보가 없다.
- Apps Script 웹앱 URL은 모든 북마클릿에 들어가므로 비밀이 아니다.
- 학번과 이름 대조는 우발적인 오입력과 단순 사칭을 줄이지만, 공개 `doPost`가 실제 u-folio 세션에서 실행됐음을 암호학적으로 증명하지는 못한다.
- 공격자가 URL과 요청 형식을 알면 자기 학번으로 조작된 값을 직접 POST할 가능성은 남는다. u-folio가 외부 검증 가능한 서명 토큰이나 인증 API를 제공하지 않는 한 이를 완전히 제거할 수 없다.
- 따라서 이 시스템은 `사이트 인증 원본을 변조 불가능하게 증명하는 시스템`이 아니라 `정상 사용자의 로그인 세션에서 자동 수집하고 감사 가능한 원본 기록을 축적하는 시스템`으로 정의한다.

## 10. 테스트 전략

### 자동 테스트

Node 내장 테스트 러너만 사용해 다음 순수 로직을 검증한다.

- `홍길동(2024-12345)` 및 공백 변형의 이름·학번 파싱
- 형식 오류와 여러 후보 거부
- 숫자 0, 소수점, 빈 값 및 `미설정` 정규화
- 여러 과·메뉴·항목 페이로드 생성
- 북마클릿 URL 생성 및 Apps Script URL 주입
- 설정 URL 누락 시 설치 차단

### Apps Script 자체 점검

관리자가 편집기에서 실행할 수 있는 테스트 함수를 제공한다.

- 필수 시트와 헤더 생성
- 등록 학번·이름 매핑 성공
- 미등록 학번 거부
- 이름 불일치 거부
- 수식 주입 문자열의 일반 텍스트 저장
- 한 전송의 여러 항목 일괄 저장

테스트 함수는 실제 학생 개인정보를 코드에 포함하지 않고 `학생명단`의 첫 데이터 행 또는 명시적 테스트 시트를 사용한다.

### 수동 통합 테스트

1. Apps Script 테스트 배포와 비공개 테스트 Spreadsheet를 준비한다.
2. Vercel 미리보기에서 공통 북마클릿을 설치한다.
3. 실제 u-folio 계정 한 명으로 임상실습요약표에서 실행한다.
4. 화면의 이름·학번 감지, 차수 목록, 과목 수, 항목 수를 확인한다.
5. `RAW`의 세 숫자 값과 u-folio 화면을 표본 대조한다.
6. `전송기록`과 전송 ID를 확인한다.
7. 재전송하여 새 전송으로 누적되는지 확인한다.
8. 이상이 없을 때 운영 Apps Script URL로 `config.js`를 바꾸고 프로덕션 배포한다.

## 11. 완료 기준

- 최종 저장소에 기존 달신 기능과 Supabase 의존성이 없다.
- `npm test`가 외부 패키지 설치 없이 통과한다.
- Vercel에서 정적 설치 페이지가 열린다.
- 모든 사용자가 동일한 북마클릿 코드를 받는다.
- 북마클릿이 현재 u-folio 로그인 사용자의 이름과 학번을 자동으로 읽는다.
- 선택한 차수의 모든 과·메뉴·항목과 승인 수·환자 수·점수를 추출한다.
- Apps Script가 비공개 명단을 기준으로 출석번호를 매핑한다.
- 성공 전송은 `RAW`와 `전송기록`에 남고, 미등록·불일치 요청은 `RAW`에 들어가지 않는다.
- 개인정보·보안 한계·배포 절차가 README에 명확히 문서화된다.
- 새 GitHub 저장소는 과거 달신 이력이 없는 새 루트 커밋에서 시작한다.
